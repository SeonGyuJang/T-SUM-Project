## 1. 발표 데이터 준비 (발표 1주 전)

- [ ] 예시 상품 3~5개 확정(Q5) — 카테고리가 서로 다른 상품
- [ ] 실제 모델이 연결된 상태에서 각 상품을 실제로 분석(`docs/model-integration.md`)
- [ ] 분석 결과를 발표 데이터로 내보내기
  ```bash
  cd service
  python -m realstar export-demo --analysis-id <an_...> --key <영문키> --query "<상품명 검색어>"
  # → apps/web/src/demo/data/<영문키>.json (더미 판별기 결과는 내보내기가 거부된다)
  ```
- [ ] `apps/web/src/demo/examples.ts`의 import 목록을 새 파일로 바꾸고, 가상 예시(vacuum/tumbler/airfryer) 제거
- [ ] 화면에 "샘플 데이터" 배지가 더 이상 보이지 않는지 확인
- [ ] 홈 "결과는 이렇게 보여드려요" 예시 카드가 실제 예시로 바뀌었는지 확인

## 2. 발표 모드 빌드·실행

```bash
cd service/apps/web
npm ci
NEXT_DIST_DIR=.next-demo NEXT_PUBLIC_DEMO_MODE=true npm run build
NEXT_DIST_DIR=.next-demo npx next start -p 3000
```
- [ ] 상단에 "발표 모드" 띠가 보인다
- [ ] 노트북 Wi-Fi를 끈 상태에서 전체 흐름이 끊김 없이 동작한다(글꼴·아이콘 모두 로컬 포함)
- [ ] 진행 화면이 약 12초 재생 후 결과로 바뀐다
- [ ] 결과에 "저장된 분석 결과"와 원래 수집 시각이 표시된다
- [ ] 예시 외 링크를 넣으면 "발표 모드에서는 예시 상품만 분석할 수 있어요"가 나온다

## 3. 화면·기기

- [ ] 해상도 1920×1080, 브라우저 확대 100%(글씨가 작으면 110%) — 핵심 숫자가 뒷자리에서 읽히는지
- [ ] 브라우저: Chrome 최신, 시크릿 창(확장 프로그램·자동완성 숨김), 북마크바 숨김
- [ ] 알림 끄기(OS 방해 금지 모드), 절전 해제, 전원 연결
- [ ] 예비 화면: `docs/screenshots/1920/` 스크린샷을 PDF로 묶어 USB·클라우드 두 곳에 준비

## 4. 시연 시나리오 초안 (3분)

| 시간 | 화면 | 말할 내용(요지) |
|---|---|---|
| 0:00–0:20 | 홈 | 문제 제기: AI가 쓴 리뷰는 사람이 거의 구분 못 함(약 50%) |
| 0:20–0:40 | 홈 입력창 → 예시 상품 링크 붙여넣기 → 분석하기 | 입력은 링크·상품명·캡처 이미지 세 가지 |
| 0:40–0:55 | 진행 화면 | 별점별 최신 100개 표본, 사람 속도로 수집, 차단 시 즉시 중단 |
| 0:55–1:40 | 결과: 핵심 비교 카드 → 별점별 구성 | 전체 ★ vs 사람 기준 ★, 신뢰구간, AI 비중. "표본 평균이 아니라 전체 분포에 반영" |
| 1:40–2:20 | Top 5 탭 전환 | 별점별 사람일 확률이 가장 높은 리뷰 |
| 2:20–2:40 | 상품명 탭 → 후보 선택(두 번째 예시) | 상품명으로도 찾을 수 있음 |
| 2:40–3:00 | 결과 하단 "결과를 읽는 방법" | 확률적 추정, 판단 보류, 쿠팡과 무관 — 한계를 함께 말하기 |
