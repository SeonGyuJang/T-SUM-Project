# 발표 리허설 체크리스트 (README 14.7)

> 2026-11-13 오너 답변: 발표는 **인터넷에 접속해 실제 서비스(Heroku)로 시연**한다. 일시·해상도는 아직 정하지 않음(Q3).
> 시연 상품은 `docs/demo-products.txt`의 실제 상품 4개(전기장판·비타민·보호필름·맥북).
> 오프라인 발표 모드는 예비용으로만 유지한다(쿠팡 차단·네트워크 장애 대비).

## 1. 실제 시연 준비 (주 경로)

수집에는 상품당 수 분이 걸리고, 그 사이 차단될 수도 있다. 그래서 **발표 전에 미리 분석해 결과 캐시를 채워 둔다.**
같은 상품을 24시간(`CACHE_TTL_HOURS`) 안에 다시 분석하면 저장된 결과가 바로 나온다.

- [ ] 실제 모델이 연결돼 있다(`/api/health`의 `detector.ready=true`, 결과에 "개발용 결과" 경고 없음)
- [ ] 발표 **전날~당일 오전**에 4개 상품을 웹에서 한 번씩 분석해 둔다(또는 `prepare-demo`, 아래 2번)
  - 발표가 하루 넘게 남았으면 Heroku config `CACHE_TTL_HOURS=72` 등으로 늘린다
- [ ] 각 결과 화면 주소(`/analyses/an_...`)를 메모해 둔다 → 차단돼도 바로 열 수 있다
- [ ] `/api/health`의 `cooldown.active=false` 확인(차단 쿨다운 중이면 새 분석이 안 된다)
- [ ] Heroku 다이노가 켜져 있다(`heroku ps -a realstar-api`), 첫 접속 지연이 없게 미리 한 번 열어 둔다

## 2. 예비: 발표 모드 (인터넷·쿠팡 문제 대비)

실제 결과를 발표 모드 데이터로 내보내면, 네트워크가 끊겨도 같은 결과로 전체 흐름을 보여줄 수 있다.

```bash
cd service
python -m realstar prepare-demo --products ../docs/demo-products.txt   # 실제 분석 → src/demo/data/p<상품번호>.json, index.ts
cd apps/web
NEXT_DIST_DIR=.next-demo NEXT_PUBLIC_DEMO_MODE=true npm run build
NEXT_DIST_DIR=.next-demo npx next start -p 3000      # 노트북에서 로컬로 실행
```
- [ ] 더미 판별기 결과는 내보내기가 거부된다 → 실제 모델 연결 후 실행
- [ ] 화면에 "샘플 데이터" 배지가 없다(가상 예시가 실제 결과로 바뀌었는지)
- [ ] 진행 화면이 약 12초 재생 후 결과로 바뀌고, "저장된 분석 결과"와 원래 수집 시각이 보인다

## 3. 시연 시나리오 초안 (시간은 Q3 확정 후 조정)

| 순서 | 화면 | 말할 내용(요지) |
|---|---|---|
| 1 | 홈 | 문제 제기: AI가 쓴 리뷰는 사람이 거의 구분 못 함(약 50%) |
| 2 | 링크 탭 → 전기장판 링크 붙여넣기 → 분석하기 | 입력은 링크·상품명·캡처 이미지 세 가지 |
| 3 | 결과: 핵심 비교 카드 → 별점별 구성 | 전체 ★ vs 사람 기준 ★, 신뢰구간, AI 비중. "표본 평균이 아니라 전체 분포에 반영" |
| 4 | Top 5 탭 전환 | 별점별 사람일 확률이 가장 높은 리뷰 |
| 5 | 상품명 탭에 "맥북" → 후보 선택 | 상품명으로도 찾을 수 있음 |
| 6 | 결과 하단 "결과를 읽는 방법" | 확률적 추정, 판단 보류, 쿠팡과 무관 — 한계를 함께 말하기 |
| (예비) | 진행 화면 | 새 상품을 실시간 분석하면 별점별 수집 진행을 보여줄 수 있다(수 분 소요) |
